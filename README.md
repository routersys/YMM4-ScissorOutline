# 縁取り（ハサミ） for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-ScissorOutline.svg)](https://github.com/routersys/YMM4-ScissorOutline/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材の不透明な部分を円盤で広げた領域の輪郭を多角形に簡略化して、ハサミで切り抜いたような縁の紙を元の映像の下に描く映像エフェクトプラグインです。
切り口は素材の不透明な部分から「太さ」以上離れ、不透明な部分はすべて紙の内側に入ります。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
切り口の形は素材の不透明度、設定、シード、コマの番号から決定論的に決まり、同じ入力と設定のフレームは何度描いても同じ形になります。
太さ、大まかさ、不揃い、手ぶれ、不透明度の5項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「縁取り（ハサミ）」として表示されます。カテゴリは加工と装飾です。

素材の不透明な部分を被写体とみなし、被写体から離れた位置を、直線の辺をつないだ多角形で囲みます。この多角形の内側を紙として塗り、元の映像の下に重ねます。紙の縁はハサミで切り抜いたように角ばった形です。

処理は次の順で進みます。

1. 素材の不透明度をCPUへ読み戻し、被写体を格子のセルに分けます。
2. 被写体のセルを円盤で広げ、広げた領域の輪郭を追います。
3. 輪郭の頂点を、許容誤差の範囲で減らして多角形にします。「不揃い」が大きいと、減らし方もばらつきます。
4. 「不揃い」と「手ぶれ」に応じて、頂点の位置をずらします。
5. 多角形の内側を紙の色で塗り、元の映像の下に重ねます。

切り口は不透明な画素の中心から「太さ」以上離れます。不透明な画素はすべて紙の内側に入ります。簡略化と、不揃いと手ぶれによるずれを加えた後も同じです。理由は「2. 切り口の位置と最小の距離」に書いています。

頂点を減らす方法はDouglas-Peuckerの方法です。この方法はHershbergerとSnoeyinkの論文「Speeding Up the Douglas-Peucker Line-Simplification Algorithm」（University of British Columbiaの技術報告TR-92-07、1992年）が示した手順に基づきます。

結果は素材の不透明度、設定、シード、コマの番号だけから決まります。時刻と、実行ごとに変わる乱数は使いません。

輪郭の計算はCPUが行い、紙はDirect2Dのパスジオメトリで描きます。フレームごとにCPUへ読み戻すのは、素材の不透明度だけを8ビットの画像にしたものです。被写体のセルと設定とコマの番号が前のフレームと同じときは、切り口の計算と紙の描き直しを省きます。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## 主な機能

### 1. 被写体とセル

処理する範囲は、このエフェクトに入る映像を囲む矩形です。この範囲の画素のうち、不透明度が255段階で8を超える画素を被写体の画素とします。不透明度が8以下の画素は、被写体として扱いません。

処理する範囲を、1辺が$`c`$画素の正方形のセルに分けます。$`c`$は2のべき乗の画素数です。被写体の画素を1つでも含むセルを、被写体のセルとします。格子の周囲には22セルの余白を足します。

$`c`$は、次の2つのうち大きい方です。

- 格子の長辺が品質ごとの上限のセル数に収まる最小の2のべき乗。上限は、標準が512、高品質が1024、最高品質が2048です。余白は数えません。
- $`T + 0.5kT + \tau + d`$を8で割った値以下で最大の2のべき乗。記号は次の節で説明します。1より小さくはなりません。

$`c`$が大きいほど、辺の位置は粗くなります。最小の距離の保証にはセルの大きさの分も含めています。

### 2. 切り口の位置と最小の距離

次の記号を使います。$`T`$は「太さ」の画素数です。$`k`$、$`u`$、$`s`$は、「大まかさ」「不揃い」「手ぶれ」を0から1の割合にした値です。

$$
\begin{aligned}
\varepsilon &= \max(0.5\,k\,T,\ c) \\
\tau &= 0.25\,s\,T \\
d &= 0.5\,u\,T
\end{aligned}
$$

$`\varepsilon`$は頂点を減らすときの許容誤差、$`\tau`$は手ぶれで頂点がずれる大きさの上限、$`d`$は不揃いで辺が被写体へ寄る大きさの上限です。被写体のセルを、次の半径$`R`$の円盤で広げます。

$$
R = T + \varepsilon + \tau + d + 1.5\,c
$$

$`R`$の各項は、後の工程で切り口が被写体へ近づく量の上限です。頂点を減らすと、辺が輪郭の内側へ最大$`\varepsilon`$寄ります。手ぶれと不揃いは頂点を内側へ最大$`\tau`$と$`d`$ずらします。$`1.5\,c`$は、セルへ丸めたときの余裕です。切り口はこれらの分だけ被写体へ近づいても、「太さ」$`T`$より近くなりません。

次の画像は文字の画像に、すべての項目を既定値にして適用した例です。

![Image](https://github.com/routersys/YMM4-ScissorOutline/blob/main/docs/ScissorOutline-Default.png)

### 3. 輪郭の追跡と簡略化

広げた領域の輪郭を、領域を右に見ながら一周たどると、外側の輪郭と、領域の中にできた穴の輪郭が得られます。「穴を埋める」がONのときは外側の輪郭だけを、OFFのときは穴の輪郭も使います。

各輪郭の頂点を、Douglas-Peuckerの方法で減らします。

1. 輪郭の中で最も上にあり、その中で最も左にある頂点を選びます。この頂点と、そこから最も遠い頂点を残して、輪郭を2つの区間に分けます。
2. 各区間で、両端を結ぶ線分から最も遠い頂点を探します。その距離が許容誤差$`\varepsilon`$より大きいときは、その頂点を残し、区間を2つに分けます。
3. これを、分ける区間が無くなるまで繰り返します。

頂点が3つ未満になった輪郭は使いません。「大まかさ」を上げると$`\varepsilon`$が大きくなり、辺が少なく長くなります。「大まかさ」が0%のときの$`\varepsilon`$はセル1つ分で、辺は広げた領域の輪郭に沿って細かくなります。

### 4. 不揃い

「不揃い」は辺の長さと、被写体から切り口までの距離を不規則にする割合です。$`u`$が大きいほど、不規則になります。

辺の長さは頂点の減らし方を変えて不規則にします。

- 区間ごとの許容誤差を、$`\varepsilon`$の$`1 - 0.75\,u`$倍から1倍の間の値にします。倍率は区間の両端の位置とシードとコマの番号から決まります。
- 区間を分ける頂点は最も遠い頂点とは限りません。両端を結ぶ線分からの距離が最も遠い頂点の$`1 - 0.75\,u`$倍以上である頂点の中から、1つを選びます。選ぶ値は区間の両端の位置とシードとコマの番号から決まります。

距離は頂点を輪郭の外向きの法線の方向へずらして不規則にします。頂点の位置を$`\mathbf{p}`$、外向きの法線を$`\mathbf{n}`$とすると、ずらした位置は次の式で表されます。

$$
\mathbf{p}' = \mathbf{p} + d\,w(\mathbf{p})\,\mathbf{n}
$$

$`w`$は$`-1`$から$`1`$の値で、波長が$`\max(16,\ 2T)`$画素の滑らかな乱数です。格子点ごとに決めた乱数を、滑らかな補間で結んでいます。$`w`$が負の場所では切り口が被写体へ寄り、正の場所では離れます。寄った場所でも、$`R`$に$`d`$を含めているため、「太さ」より近くはなりません。$`d`$の分だけ広げた領域が大きくなるため、「不揃い」を上げると、紙は平均して厚くなります。

次の画像は同じ画像に、「不揃い」を左から0%、50%、100%にして適用した例です。ほかの項目は既定値です。

![Image](https://github.com/routersys/YMM4-ScissorOutline/blob/main/docs/ScissorOutline-Irregularity.png)

### 5. 手ぶれ

「手ぶれ」は頂点を小さくずらす割合です。各頂点を、位置とシードとコマの番号から決まる向きと量でずらします。縦と横のずれは、それぞれ$`\pm \tau / \sqrt{2}`$以内なので、ずれの大きさは$`\tau`$を超えません。

### 6. コマ打ちとシード

コマ打ちは1枚の絵を何フレームか続けて使う作り方です。アイテムの先頭から数えたフレームの番号を$`f`$、「コマ打ち」を$`h`$とすると、コマの番号は$`\lfloor f / h \rfloor`$です。シードとコマの番号から1つの値を作り、手ぶれと不揃いの乱数の元にします。

同じコマの間は、手ぶれと不揃いの乱数が同じです。コマが替わると乱数が替わり、切り口の形が替わります。「コマ打ち」を1にすると毎フレーム替わり、シードを変えるとすべてのコマの乱数が替わります。

「手ぶれ」と「不揃い」がともに0%のときは、シードとコマ打ちは形に影響しません。

### 7. 紙の描画

切り口の多角形を、Direct2Dのパスジオメトリとして描きます。塗りつぶしの規則は、巻き数が0でない範囲を塗る規則です。「穴を埋める」がOFFのとき、穴の輪郭は外側の輪郭と回る向きが逆なので、穴の中は塗られません。

紙は元の映像の下に重ねるため、被写体は紙の色の上にそのまま見えます。紙の不透明度は「不透明度」に色の不透明度を掛けた値です。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- 次のときは、紙を描かず入力映像を表示します。「太さ」が0pxのとき、紙の不透明度が0のとき、処理する範囲の幅か高さが4096画素を超えるとき、被写体の画素が1つも無いときです。紙の不透明度は「不透明度」に色の不透明度を掛けた値です。
- 切り口は直線の辺だけでできています。曲線や丸い角は作りません。
- 保証する距離は、不透明度が8を超える画素の中心から切り口までの距離です。不透明度が8以下の画素と、画素の角までの距離は保証しません。
- 被写体どうしが近いと、広げた領域がつながり、1枚の紙になります。被写体に囲まれた穴のうち、穴の中のどこでも被写体から$`R`$以内にある小さな穴は、「穴を埋める」をOFFにしても紙で埋まります。
- 半透明の被写体の画素も、不透明度が8を超えれば被写体として扱います。紙は元の映像の下に重ねるため、半透明の部分には紙の色が透けて見えます。
- セルが大きいと、辺の位置はセルの大きさの単位で決まります。素材が大きいときは、「品質」を上げるとセルが小さくなります。「太さ」が大きく、セルの大きさが太さから決まるときは、「品質」を上げてもセルは小さくなりません。
- 切り口は次の方法で確かめています。
  - 円盤、環、線、塊、点の画像を使い、「太さ」「大まかさ」「手ぶれ」「不揃い」「品質」「フレーム」の組み合わせを変えます。どの組み合わせでも、切り口から被写体の画素の中心までの距離が、「太さ」から0.01画素を引いた値以上であることを確かめています。
  - 同じ画像と組み合わせで、被写体の画素の中心がすべて紙の内側にあることを確かめています。
  - 不揃いが100%で、塊の画像に対して、3つのシードと12のフレームでも同じことを確かめています。

## 注意事項

- 処理負荷: フレームごとに、素材の不透明度をCPUへ読み戻し、セルに分けます。被写体のセル、設定、コマの番号のどれかが前のフレームと違うときは、切り口を計算し直して紙を描き直します。「太さ」「大まかさ」「不揃い」「手ぶれ」をアニメーションで動かすと、動かしている間はフレームごとに切り口を計算し直します。「不透明度」を動かすと、フレームごとに紙だけを描き直します。
- 平均の厚さ: 「不揃い」を上げると、紙は平均して厚くなります。「太さ」は切り口と被写体の最小の距離です。
- 再現性: 結果は素材の不透明度、設定、シード、コマの番号だけから決まります。時刻と、実行ごとに変わる乱数は使いません。同じフレームは何度描いても同じ形になります。
- コマ打ち: コマの番号はアイテムの先頭から数えたフレームの番号から決まります。コマの番号が同じなら、アイテムをタイムラインのどこに置いても、手ぶれと不揃いの乱数は同じです。
- 処理する範囲の外: 紙は、処理する範囲の外にも広がります。被写体が処理する範囲の端に接していても、紙は端で切れません。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、破棄するときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
